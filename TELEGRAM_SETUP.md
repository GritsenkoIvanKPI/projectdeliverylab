# Заявки з сайту в Telegram — налаштування

Сайт: **projectdeliverylab.com**, хостинг **Hostinger**.

Форма «Надіслати заявку» шле дані на `send-form.php`, а той пересилає їх у
Telegram. Токен бота лежить у `config.php` **тільки на сервері** — у git його
немає і браузеру він не віддається.

```
браузер  ->  send-form.php  ->  api.telegram.org
                   ^
              config.php  (токен, ніколи не комітиться)
```

---

## 1. Створити бота

1. У Telegram знайти **@BotFather** → `/newbot`.
2. Задати імʼя та username (username має закінчуватись на `bot`).
3. BotFather віддасть токен виду `1234567890:AAH...`. **Це пароль від бота** —
   не пересилати в чатах, не класти в git.

## 2. Дізнатися chat_id

Заявки зручніше приймати в групу: туди можна додати менеджерів, і історія
лишається спільною.

1. Створити групу, додати в неї бота.
2. Написати в групу будь-що (боти не бачать повідомлень до першого).
3. Відкрити в браузері:
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates`
4. Знайти `"chat":{"id":-1001234567890,...}` — це і є `chat_id`.
   У групи він відʼємний, у приватного чату — додатний.

Якщо `getUpdates` віддає порожній `result` — напишіть у групу ще раз і оновіть
сторінку.

## 3. Завантажити файли на Hostinger

У **hPanel → Файловий менеджер**, у папку `public_html`:

```
public_html/
├── index.html
├── send-form.php        ← обробник форми
├── config.php           ← створюємо на кроці 4, у git його немає
├── .htaccess            ← закриває config.php, вмикає кеш і стиснення
├── robots.txt
├── sitemap.xml
├── site.webmanifest
└── assets/              ← уся тека цілком
```

`config.example.php` і `*.md` на сервер завантажувати не треба.

**PHP має бути увімкнений.** hPanel → Додатково → Конфігурація PHP → версія
**8.0 і вище**.

## 4. Створити config.php на сервері

У файловому менеджері поруч з `index.html` створити файл `config.php`
(за зразком `config.example.php`) і вписати свої значення:

```php
<?php
return [
    'bot_token' => '1234567890:AAH...',      // від BotFather
    'chat_id'   => '-1001234567890',         // з кроку 2
    'notify_email' => '',                    // дублювати на пошту, порожньо = вимкнено
    'rate_limit_per_hour' => 5,              // заявок з однієї IP за годину
];
```

Файл створюємо **прямо на сервері**. Локальний `config.php` у git не потрапляє —
про це подбає `.gitignore`.

## 5. Перевірити

**Самодіагностика.** Відкрити в браузері:

```
https://projectdeliverylab.com/send-form.php?selftest=1
```

Має бути приблизно так:

```json
{
  "ok": true,
  "php_ok": true,
  "config_present": true,
  "token_present": true,
  "chat_id": "-1001234567890",
  "can_send": true
}
```

Токен не друкується — лише чи він є. Якщо `config_present: false` — файл не в тій
теці. Якщо `can_send: false` — на тарифі немає ні cURL, ні `allow_url_fopen`,
треба звернутись у підтримку Hostinger.

**Бойова перевірка.** Заповнити форму на сайті й переконатись, що повідомлення
прийшло в групу.

## Що надходить у Telegram

```
🎓 Нова заявка — Project Delivery Lab

Імʼя: Олена Ковальчук
Контакт: +380 66 111 22 33

Звідки: Тарифи
Сторінка: /
11.09.2026 14:44
```

Номер загорнутий у `<code>` — у Telegram він копіюється одним дотиком.

Рядок **«Звідки»** показує, яка саме кнопка привела людину до форми: «Тарифи»,
«Програма курсу», «Головний екран» тощо. Видно, який блок реально продає.

## Що робить скрипт

- **Пастка для ботів.** У формі є приховане поле `website`. Людина його не
  бачить; бот, який заповнює все підряд, отримує «успіх», але повідомлення не
  надсилається — тож у нього немає сигналу повторювати спробу.
- **Ліміт частоти.** Не більше `rate_limit_per_hour` заявок з однієї IP за
  годину (типово 5). Понад це — `429`.
- **Валідація на сервері.** Імʼя від 2 символів; контакт — або номер (від 9
  цифр), або нік Telegram (`@nick`, `t.me/nick`); згода на обробку даних
  обовʼязкова. Запит повз сторінку теж перевіряється.
- **Екранування.** HTML у полях перетворюється на текст — підробити розмітку
  чи посилання в повідомленні не вийде.
- **Захист від інʼєкції заголовків** — переводи рядка в імені чи контакті
  відхиляються.
- **Копія на пошту** — необовʼязково, через `notify_email`.

## Що бачить відвідувач

| Ситуація | Повідомлення |
|---|---|
| Успіх | Екран «Заявку надіслано» замість форми |
| Незаповнені поля | Поля підсвічуються, форма не відправляється |
| Забагато заявок | «Ви вже надіслали кілька заявок. Спробуйте за годину…» |
| Немає `config.php` | «Форма тимчасово не працює. Напишіть у Telegram…» |
| Telegram недоступний | «Не вдалося надіслати заявку. Спробуйте ще раз…» |
| Немає інтернету | «Немає звʼязку з сервером…» |

Форма при помилці лишається заповненою — нічого набирати заново не треба.

## Якщо заявки не приходять

1. Відкрити `?selftest=1` — перевірити `config_present`, `token_present`,
   `can_send`.
2. Переконатись, що бот **доданий у групу** і група та сама, що в `chat_id`.
3. Подивитись лог помилок PHP: hPanel → Файловий менеджер → `error_log` поруч з
   `index.html`. Скрипт пише туди причину відмови Telegram.
4. Перевірити версію PHP — потрібна 7.4+, краще 8.x.

## Локальна перевірка (для розробника)

```bash
# у теці проєкту, з тимчасовим config.php поруч
docker run --rm -v "$PWD":/app -w /app -p 8080:8080 php:8.2-cli php -S 0.0.0.0:8080
# далі відкрити http://localhost:8080/
```

`node serve.mjs` роздає тільки статику — PHP він не виконує, тому форму через
нього перевірити не вийде.
